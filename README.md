API RESTful para gerenciamento de um catálogo de Pokémon, desenvolvida em **TypeScript** com **Express**, seguindo os princípios de **Clean Architecture**.

Projeto desenvolvido para a disciplina de Tópicos Especiais em Engenharia de Software (UFF).

## Funcionalidades

- Listagem de Pokémon, com filtro opcional por tipo
- Busca de um Pokémon específico por ID
- Cadastro de novos Pokémon
- Atualização parcial de dados de um Pokémon
- Remoção de um Pokémon do catálogo
- Estatísticas gerais do catálogo (total de registros e contagem por tipo)
- Documentação interativa via Swagger / OpenAPI 3.0

## Arquitetura

O projeto segue os princípios de **Clean Architecture**, organizando o código em camadas com responsabilidades bem definidas:

```
src/
├── domain/           # Entidades e contratos (interfaces) de repositório
│   ├── entities/
│   └── repositories/
├── application/      # Casos de uso (regras de negócio da aplicação)
│   └── use-cases/
├── infrastructure/    # Implementações concretas (banco de dados, HTTP)
│   ├── database/
│   └── http/
│       └── controllers/
└── main/             # Ponto de entrada, rotas e injeção de dependências
    ├── config/
    ├── factories/
    └── server.ts
```

**Fluxo de dependências:** `main` → `infrastructure` → `application` → `domain`

A camada de `domain` não depende de nenhuma outra camada, o que permite trocar a implementação de persistência (atualmente em memória) por um banco de dados real sem impactar as regras de negócio.

## Pré-requisitos

- [Node.js](https://nodejs.org/) 18 ou superior
- npm

## Instalação

```bash
# Clone o repositório
git clone https://github.com/seu-usuario/pokemon-manager-api.git

# Acesse a pasta do projeto
cd pokemon-manager-api

# Instale as dependências
npm install
```

## Executando o projeto

### Gerar a documentação do Swagger

```bash
npm run swagger
```

> Rode este comando sempre que adicionar ou alterar uma rota.

### Iniciar o servidor em modo desenvolvimento

```bash
npm run dev
```

O servidor estará disponível em `http://localhost:3333`.

## Documentação da API

Com o servidor em execução, acesse a documentação interativa (Swagger UI) em:

```
http://localhost:3333/api/docs
```

Nela é possível visualizar todos os endpoints disponíveis e testá-los diretamente pelo navegador.

## Endpoints

| Método | Rota                      | Descrição                                  |
|--------|---------------------------|---------------------------------------------|
| GET    | `/api/v1/pokemons`        | Lista todos os Pokémon (filtro opcional `?type=`) |
| GET    | `/api/v1/pokemons/stats`  | Retorna estatísticas gerais do catálogo     |
| GET    | `/api/v1/pokemons/:id`    | Busca um Pokémon pelo ID                    |
| POST   | `/api/v1/pokemons`        | Cadastra um novo Pokémon                    |
| PUT    | `/api/v1/pokemons/:id`    | Atualiza um Pokémon existente               |
| DELETE | `/api/v1/pokemons/:id`    | Remove um Pokémon do catálogo               |

### Exemplo de corpo de requisição (POST / PUT)

```json
{
  "id": "25",
  "name": "Pikachu",
  "type": "Electric",
  "hp": 35
}
```

## Qualidade de código

O projeto conta com ESLint e Prettier configurados e integrados, garantindo padronização e detecção de problemas comuns.

```bash
# Verifica problemas de lint
npm run lint

# Formata o código automaticamente
npm run format
```

## Persistência de dados

Atualmente, o projeto utiliza um repositório **em memória** (`InMemoryPokemonRepository`), o que significa que os dados são reiniciados sempre que o servidor é reiniciado. Essa implementação segue o contrato definido pela interface `IPokemonRepository`, permitindo a substituição futura por um banco de dados real sem alterar as demais camadas da aplicação.
